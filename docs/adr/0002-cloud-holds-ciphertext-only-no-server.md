# 多设备同步信任模型：云端只存密文，无自建服务端

多设备使用（多台家用电脑 + 手机）曾考虑三种形态：家里电脑作服务器供其他设备远程访问、自建公网 VPS 部署本应用、以及每台设备本地运行应用而云端只存放 `vault.pvlt` 密文副本。我们选了第三种：同步通道为坚果云（桌面端经其客户端同步的本地目录，手机端经 WebDAV），信封加密保证云盘永远接触不到明文。

被否决方案的理由：VPS/家用服务器方案要求把一个可解密全库凭据的服务长期暴露（给家里电脑开远程访问，一旦配置失误即公网可达），安全边界的扩大不可控；且家用电脑关机即全员不可用。坚果云几百 KB 密文的流量在其免费额度内，成本近零。

## 后果

- 曾计划的"公司电脑临时使用"场景在拷问中被**整体删除**：该模型要求公司机器能运行本应用或访问受控服务，与"不能装环境"的前提无法调和；应急查看需求由移动端承接。
- 同步时机为事件驱动：解锁前向云端校验基准版本、保存后推送，不做后台轮询。
- 所有身份档的密文副本默认全部上云，不提供逐档排除开关（敏感档隔离需求将来出现时另行决策）。
- 桌面绿色免安装打包（单文件 exe）降级为可选项，不阻塞同步主线。
