# 桌面分发形态：免安装绿色包走 GitHub Release 附件

ADR 0002 曾把"桌面绿色免安装打包（单文件 exe）"列为不阻塞同步主线的可选项。真正落地时形态变了：分发单位是**解压即用的绿色包**（内置 Node 运行时的目录 + 一个双击即启动的 `.bat`），以 **GitHub Release 附件**发布，而不是当初设想的单文件 exe，也不是安装向导。理由是包只是运行环境的搬运——服务端入口、界面、加密信封与数据位置都和仓库启动方式一致，换形态不改变任何行为；而单文件打包要么把已验证的 scrypt/AES 运行时换成另一套（密码库项目上不赌这个），要么引入 Electron 那量级的壳与主进程改造。代码签名要买证书，当前分发范围（发给认识的人自用）不值得，靠包内说明的"右键属性→解除锁定"绕过 SmartScreen 即可。

## 后果

- **两条启动入口是并行设计，不分新旧**：技术人员从仓库启动（`启动密码库.cmd`，需本机 Node 24 与 `npm install`），非技术用户用绿色包（`.bat`，什么都不用装）。两者最终执行同一个 `dist-server/server/index.js`；打包脚本在组装前断言产物存在，所以不会悄悄分叉。
- **包不进 git 仓库**（`release/` 已忽略），只作为 Release 附件存在；获取渠道因此成为交付的一部分——发版必须同时更新附件与 README 的下载直链。
- **旧版本附件保留不删**，只在正文顶部标注已被哪个版本取代；链接不能断，别人手里那份要对得上号。
- 未签名是**已知取舍**而非待办：分发范围一旦扩大到陌生人下载，需要重新评估签名与安装器。
