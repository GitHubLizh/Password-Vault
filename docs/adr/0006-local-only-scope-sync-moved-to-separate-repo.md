# 项目范围收敛为纯本地保存，多设备同步移交独立仓库

2026-09-30 决定：本仓库只做单机本地保存——数据在磁盘 `vault.pvlt`、服务只监听 `127.0.0.1`、跨设备靠导出加密备份再导入。多设备同步（含手机端）另开新仓库专门做，本仓库不再承接其工单。

## 后果

- **同步铺垫代码当天删除**：`server/sync/provider.ts` 接缝（连同 `buildApp` 与 `VaultService` 的注入点）、`shared/merge.ts` 三方合流纯函数、`tests/merge.test.ts`、`tests/sync-provider.test.ts` 及其 fake 辅助全部移除，测试从 129 项降到 106 项。新仓库若要同源实现，从 git 历史取回；本仓库不留进不去的接口。
- **同步规格说明移出本仓库**：`docs/specs/2026-09-29-多设备同步.md` 已从版本库删除，副本暂存 `.scratch/多设备同步/`（不入库），待新仓库接手。
- ADR 0002（云端只存密文、无自建服务端）、0003（合流字段进加密载荷、信封保持 version 1）、0004（移动端纯前端托管 GitHub Pages）加状态行标为移出本项目，只作决策历史保留；其中 0003 的"信封保持 version 1"这一半**仍然约束本仓库**——`vault.pvlt` 格式不变。`同步副本 / 基准版本 / 条目级合流 / 解锁基线 / 移动端` 五个术语已从 `CONTEXT.md` 移除，由新仓库自建术语表。
- README 的"无跨设备同步；换机器需手动迁移存储目录或导入备份"从**已知限制**变成本项目的**边界声明**：它不是待补的缺口，是设计意图。
- 分发（ADR 0005 的绿色包）只服务单机场景；任何"多设备"诉求一律指向新仓库，不在本仓库加同步半成品。
