# 回收站存放在加密密码库内，保留 30 天并在载入时清除

2026-10-20 决定：删除条目不再立即丢弃，而是移入回收站——`VaultSnapshot` 新增 `trash` 数组，条目打上 `deletedAt` 后从 `entries` 移入其中。回收站随密码库整体加密（仍是单个 `vault.pvlt`，信封格式不变），条目保留 30 天，到期在解锁或恢复备份的载入路径上自动清除并持久化。

## 后果

- **旧文件无需迁移**：`snapshot()` 校验时把缺失的 `trash` 字段视为空数组，旧密码库与旧加密备份可直接打开；条目编号在 `entries` 与 `trash` 的合并集合内唯一。
- **恢复保身份**：从回收站恢复保留原条目 id 与 `createdAt`（`updatedAt` 置为恢复时间，回到列表顶部）；因此删除后的「撤销删除」Toast 也改走恢复接口，不再是"按内容重建"。
- **清除时机是载入时**：只有解锁/恢复备份时才真正删除过期条目并写盘——永不解锁的库不会在磁盘上变小，但也绝不会在无人在场时被改写。
- **彻底删除有两档**：单条彻底删除走确认对话框；「清空回收站」额外要求服务端 `confirmed: true`，与删除身份档、迁移存储的二次确认风格一致。
- 回收站条目不参与搜索与分类计数、不可编辑（`PUT /api/entries/:id` 对回收站中的 id 返回 404），秘密在回收站详情里同样默认掩码。
- 回收站计入 `MAX_VAULT_BYTES` 与 10000 条上限，恢复在条目已满时被拒绝。
