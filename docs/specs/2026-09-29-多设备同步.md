# 规格说明：多设备同步（云端只存密文）

日期：2026-09-29
依据：ADR 0002 / 0003 / 0004，CONTEXT.md 术语（同步副本、基准版本、条目级合流、解锁基线、移动端）

## 1. 问题陈述

应用目前是单机工具：服务端只监听 `127.0.0.1`，数据是本地磁盘上的 `vault.pvlt`，README 明示"无跨设备同步；换机器需手动迁移"。用户在家用多台电脑日常记录凭据、在手机偶尔查看和使用，现有唯一跨设备手段是导出加密备份再人工导入——多台设备并行编辑时没有任何合流能力，后写入者静默覆盖先写入者。

## 2. 方案概述

每台设备本地运行应用，云端（坚果云）只存放各身份档 `vault.pvlt` 的**同步副本**（密文）。不存在任何自建服务端组件：

- **桌面端**：存储目录设在坚果云客户端的本地同步目录上；应用经 WebDAV 只做两件事——解锁前查远端版本（拉校验）、保存后确认远端追上本地（推确认）。
- **移动端**：GitHub Pages 托管的独立纯前端页面（独立私有仓库），经 WebDAV 直接拉取/写回密文，浏览器内 scrypt-WASM 解密。与本仓库共享同一份合流实现和信封格式。
- **冲突**：保存前校验基准版本；分叉时执行条目级合流，以解锁基线为 base 做三方对比，自动合入单方改动，真冲突逐项交用户裁决。信封保持 version 1 不动（ADR 0003）。

### 接缝草图（测试与实现的稳定接口）

| 接缝 | 形态 | 现状 |
| --- | --- | --- |
| HTTP API | `buildApp({directory, origin, now, folderPicker})` + light-my-request | 已存在（tests/helpers/vault-fixture.ts），同步行为在此层可测 |
| SyncProvider | 新接口：`listProfiles() / remoteVersion(id) / download(id) / upload(id, bytes, baseline)` | 新增；注入方式与 folderPicker 同款，测试用内存 Fake，生产用 WebDAV 实现 |
| merge() | 纯函数 `(base, local, remote, decisions?) → {merged?, conflicts?}`，放 `shared/` | 新增；桌面端与移动端共用同一份（ADR 0004 要求移动端复用） |
| 信封/解密 | `server/crypto.ts` parseEnvelope/decrypt/encrypt | 已存在，**零改动**（版本保持 1） |

## 3. 用户故事

每条可独立验证。前缀标出主验证接缝。

### A. 同步配置（HTTP API / 前端）

- **US-01** 作为用户，我在设置页填入坚果云 WebDAV 地址、账号和应用密码，点"测试连接"，应用列出远端身份档或给出明确错误，成功后配置持久化。
- **US-02** 作为用户，我的凭据（WebDAV 应用密码）只存在本机配置文件中（0600 权限），绝不写入任何 `vault.pvlt`、绝不进入同步内容。
- **US-03** 作为用户，若存储目录不在坚果云本地同步目录内（路径不含/不等于其同步根），应用给出警告并说明"保存后推送确认将不可用"，但不阻止使用（退化为纯拉校验）。
- **US-04** 作为用户，我没有配置同步时，应用一切行为与现状完全一致（同步是可选叠加层，不是新前提）。

### B. 解锁前拉校验（SyncProvider + HTTP API）

- **US-05** 作为用户，解锁某身份档时，应用先查远端同步副本的基准版本；远端比本地新，则等云盘客户端把新密文落到本地后再解锁——我看到的是最新库。
- **US-06** 作为用户，云盘客户端离线或落地超时（上限如 10 秒）时，应用仍用本地副本解锁，进入"离线模式"标识；不因为云端不可达而拒绝我解锁。
- **US-07** 作为用户，解锁成功后应用记住解锁基线（解密快照 + 密文指纹），界面不感知这一内部状态。
- **US-08** 作为用户，移动端与桌面端看到同一组身份档列表（远端目录枚举结果与本地档案事实源一致，因为唯一事实源就是磁盘/云上的 `vault.pvlt`）。

### C. 保存后推确认（SyncProvider）

- **US-09** 作为用户，每次保存写本地成功后，界面出现同步状态：同步中 → 已同步（远端内容与本地密文指纹一致）；确认超时则显示"未同步"，本地写入不回滚。
- **US-10** 作为用户，处于"未同步"状态时我继续编辑保存，状态照常推进；下一次解锁的基准版本校验负责兜底，不存在静默丢数据。

### D. 基准版本校验与条目级合流（merge 纯函数 + HTTP API）

- **US-11** 作为用户，保存时若远端同步副本已偏离我的解锁基线，应用阻止直接覆盖，转入合流流程。
- **US-12** 作为用户，只有单方改动的条目（新增/修改/删除各只发生在一边）被自动合入，不打扰我。
- **US-13** 作为用户，同一条目双方都改过时，我逐项看到两版内容对照（含各自 updatedAt 时间展示），选择保留哪一版或手工合并；裁决完成前不落盘。
- **US-14** 作为用户，合流后的库以我的解锁密钥重新加密保存，密文正常推上云；信封仍是 version 1，其他未升级设备照常能解。
- **US-15** 作为用户，任何一次合流不静默丢弃条目：每一条被合入或裁决的条目都能溯源到 base/本地/远端三方之一；合流前应用保留本轮分叉的远端密文副本用于事后回查（保留在本机，不进云）。
- **US-16** 作为用户，时间戳只用于展示与裁决辅助，合流正确性不依赖跨设备时钟先后（时钟偏移不产生错误合流）。

### E. 身份档生命周期（SyncProvider）

- **US-17** 作为用户，新建身份档后的首个密文随正常保存流程推上云，其他设备下次拉列表即可见。
- **US-18** 作为用户，删除身份档沿用现有流程（本地删 + 安全备份）；云盘目录代理会把删除同步过去（进坚果云回收站），移动端列表随之消失。
- **US-19** 作为用户，`profiles.json`（默认档显示名）不参与同步，各设备本地自治——显示名不一致是可接受代价，换取"配置损坏不丢数据"的档案事实源原则不被稀释。

### F. 移动端（契约测试；实现位于独立私有仓库）

- **US-20** 作为用户，手机浏览器打开 Pages 页面，经 WebDAV 枚举身份档、输入主密码本地解密（hash-wasm scrypt，参数与信封 v1 完全一致），浏览/搜索/复制条目。
- **US-21** 作为用户，我在手机端新增、修改、删除条目，写回前执行与桌面端同款的基准版本校验与条目级合流（调用与桌面共享的 merge 实现）。
- **US-22** 作为用户，主密码与解密内容只存在于页面内存，不进任何存储（localStorage/IndexedDB 均不写秘密）；页面关闭即无痕。
- **US-23** 作为用户，若坚果云 WebDAV 对浏览器 PUT 的 CORS 实测不通过，手机端降级为只读（ADR 0004 后果条款），且此结论回写本 spec 与 ADR。
- **US-24** 作为维护者，移动端代码仓库独立私有，构建产物发布到 GitHub Pages；本公开仓库不包含移动端源码，push 前的密钥扫描红线不因 Pages 流程放松。

### G. 兼容与回归

- **US-25** 作为老用户，我的既有 `vault.pvlt` 与历史导出的加密备份在升级后照常解锁、合流、推送——载荷字段（条目 id/updatedAt/revision）本就存在，无数据迁移。
- **US-26** 作为用户，修改主密码、备份恢复、存储迁移、自动锁定等现有功能语义不变；其中备份恢复的"整库替换"与合流互不干扰（恢复写本地后照常走推确认）。
- **US-27** 作为用户，界面新增状态可见：已同步/未同步/离线模式/待合流，均用现有石墨黑+青色系，不引入新视觉语言。

## 4. 已定决策（拷问共识，勿翻案）

1. 云端只存密文，无自建服务端（ADR 0002）；否决：家用服务器、公网 VPS。
2. 通道 = 坚果云；桌面经云盘客户端目录代理，手机经 WebDAV 直连。
3. 全部身份档无条件参与同步，无逐档开关。
4. 对表时机 = 解锁拉校验 + 保存推确认，无后台轮询。
5. 冲突策略 = 保存时检测 + 条目级合流（三方对比，base = 解锁基线）。
6. 信封保持 version 1；基准版本 = 密文 sha256 + WebDAV ETag，存于信封之外（ADR 0003，延续 ADR 0001 守卫）。
7. 移动端可编辑写回、GitHub Pages 托管、代码放独立私有仓库；scrypt 走 WASM。
8. 公司电脑场景已整体删除；绿色免安装打包降级为可选项，不入主线。
9. CORS 验证失败时手机降级只读，不建中转服务。

## 5. 测试决策

- **merge() 纯函数**（最高价值接缝）：`node:test` 表驱动单测——单增/单删/单改/双改/三方组合、空库、上限 10000 条内的性能冒烟。桌面与移动共享此测试套件，即 ADR 0004 要求的契约测试。
- **SyncProvider 接口层**：内存 Fake provider 注入 `buildApp`（与 folderPicker 同款），复用 tests/helpers/vault-fixture.ts 的 HTTP 接缝验证 US-05～US-11 的编排行为（拉校验时序、推确认状态机、离线降级）。
- **真实 WebDAV**：只做手工冒烟脚本（不进 CI）：坚果云测试账号上 list/get/put + ETag 语义确认。**前置实验**（拆票时排第一）：浏览器 Origin 视角的 CORS 探测 GET/PUT/PROPFIND，决定 US-21 是否降级为 US-23。
- **Playwright**：桌面冲突裁决 UI（US-13 交互）与同步状态徽标（US-09/US-27）各一条端到端用例，配合 Fake provider。
- **完成定义**：typecheck + `npm test` 全绿；US 编号逐条有测试或手工验证记录；README「已知限制」的"无跨设备同步"条目改写为同步说明（含 8MiB 上限、免费额度说明）。

## 6. 明确不做

- 多用户协作/共享库（同步的是同一个人的多台设备）。
- 实时变更推送（他端改动只在解锁/保存对表时被发现）。
- 后台轮询、常驻同步进程。
- 逐身份档同步开关、敏感档本地隔离。
- 中转/代理服务器解决 CORS（失败即降级只读）。
- 绿色免安装单文件打包（可选项，另案）。
- 公司电脑场景。
- 明文预览进云端（含缩略图、元数据索引、文件名加密等一切花样）。
- `profiles.json`、安全备份副本（before-restore/before-delete）、write-lock、临时文件的同步——同步单元**只有**各身份档 `vault.pvlt`。

## 7. 补充说明

- **坚果云免费额度**（3GB 上行/月）对几百 KB 级密文绰绰有余；但云盘客户端同步有秒级~分钟级延迟，US-09 的"已同步"判定必须等远端指纹追上，超时阈值建议在实现期实测调参。
- **WebDAV ETag 语义待实测**：若坚果云 ETag 不是内容哈希，推确认需回读密文比对 sha256（流量小可接受），或退化为"上传后固定等待+抽样回读"。
- **write-lock 与云盘竞争**：云盘客户端写本地目录时应用正在读，现有 `FILE_CHANGED` 指纹守卫（vault.ts:181）应能兜住，但要在测试里显式构造"远端落地发生在会话中途"的场景。
- **8 MiB 单文件上限**（crypto.ts:6）不变；整库读写开销随条目数上升的问题在多设备下更敏感，留待将来性能案。
- 身份档主线工单 001–011 已全部实现并提交（git 5f297bc～9e19d86，2026-09-29 核对），本功能无主线阻塞，可直接开工。
